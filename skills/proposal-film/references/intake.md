# 需求访谈

目的：把"想做个求婚视频"问到能画分镜的程度，而且每个情节都有真事撑着。一次问一组（3–6 个问题），先给一个初步方向让用户有东西可以反应，再追问。给用户自己拿去问任何 AI 的版本在 `templates/01-挖故事提示词.md`。

## 先问清楚的（决定形式）

| 问题 | 决定什么 |
|---|---|
| 在哪放？电视、投影、手机？对方会不会起疑？ | 横竖屏、字号、结尾卡停多久、真人怎么接 |
| 求婚定在哪天？ | 倒推制作周期；结尾日期写什么 |
| 想要什么基调：感人、搞笑、电影感？ | 节奏和画风的大方向 |
| 预算大概多少？ | 用什么模型、出几轮草稿 |
| 用哪首歌？有没有一起听过的歌？ | 整片结构。共同的记忆比歌词贴切更重要；也要查歌词，失恋歌不能用 |

## 要挖的故事（决定内容）

- **怎么认识的**：谁介绍的？人物之间是什么关系？案例里是一条"朋友的朋友"的关系链，后来画成了三格漫画加一条红线。用户不想讲的部分直接跳过，只要场景。
- **确定关系那天**：谁先开口，说了什么，在哪里，前一天做了什么。
- **热恋时常做的事**：越日常越好，比如打球（谁总输、谁不跑动）、给她拍照、做蛋糕、撸猫。问到具体的画面和好笑的细节。
- **最难的时候**：异地、加班、生病。怎么见面、多久见一次、视频时通常在干什么。**不要主动提议编吵架**；问"那段时间你是怎么让她开心的"，往往能问出真正的低谷和治愈（案例里是她累到想哭，他在视频里做鬼脸把她逗笑）。
- **他的习惯动作**：逗她的招牌动作。可以当贯穿全片的线，结尾"最后一次不开玩笑"就是从这里来的。
- **一起去过的地方**：每个地方一个记得最清楚的画面。
- **现在的日常**：柴米油盐，比如做饭、一起看电视。
- **对方喜欢什么**：花、颜色、电影类型。用来定暗号物件和画风。
- **素材**：合照（按时间拍的越多越好）、婚纱照、有没有视频。照片的拍摄时间可能是错的（相机时间被还原过），要和用户核对。

## 人物资料

- 两位主角和关键配角的真人照片各一张以上，用来定人设。照片只给生图工具当参考，不要放进公开的地方。
- 身材、发型要用户确认。案例里被纠正过两次：主角"没那么胖，偏瘦高"，配角又"画得过于胖了"。
- 主角和配角的称呼（片子里用小字标签），以及他们之间的关系。

## 问完之后

先写"一句话故事"，再写章节方案和要补的素材清单。章节方案用户点头之前，不出图也不花钱。
